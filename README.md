# HP Watcher v2.4

Следит за полосками HP/MP в Lineage 2 и нажимает клавиши по условиям:
«цель убита», «моё HP меньше 40%» и т. п.

## Установка

1. Установите Python 3.10+ с python.org, при установке отметьте **Add python.exe to PATH**.
2. Один раз в консоли: `pip install -r requirements.txt`
3. Запуск: двойной клик по `run.bat`. Скрипт сам попросит права администратора
   (без них Windows не пропускает нажатия в игру, запущенную от администратора).

Хотите `.exe` без Python? Запустите `build.bat`, и в папке `dist` появится `HPWatcher.exe`.

Игра должна быть в **оконном режиме** или в «окне без рамки», иначе оверлей не будет виден.

## Первая настройка (1 минута)

Все сочетания — **Ctrl+Alt+цифра**, чтобы не конфликтовать с F1–F12 и 1–0 в игре.

| Сочетание | Что делает |
|---|---|
| Ctrl+Alt+5 | привязаться к окну игры (нажимать, когда игра активна) |
| Ctrl+Alt+4 | автопоиск полосок |
| Ctrl+Alt+3 | выбрать полоску для ручной калибровки: цель → моё HP → моё MP |
| Ctrl+Alt+1 / 2 | левый / правый край выбранной полоски под курсором мыши |
| Ctrl+Alt+6 | запись последовательности клавиш вкл/выкл |
| Ctrl+Alt+7 | тестовый режим вкл/выкл (без нажатий) |
| Ctrl+Alt+8 | вывести статистику в лог и обнулить |
| Ctrl+Alt+T | проверка: сразу выполнить сценарий «После убийства моба» |
| Ctrl+Alt+S | окно настроек (или кнопка «⚙ Настройки» в окне статуса) |
| Ctrl+Alt+0 | пауза / продолжить, снять аварийную паузу (или двойной клик по окну статуса) |
| Ctrl+Alt+9 | перечитать config.json |
| Ctrl+Alt+End | выход |

1. Зайдите в игру и нажмите **Ctrl+Alt+5**.
2. Возьмите в цель моба с полным HP (свои HP/MP тоже должны быть полными) и нажмите **Ctrl+Alt+4**.
3. На экране появятся рамки вокруг найденных полосок: жёлтая — цель, зелёная — моё HP, голубая — MP.
   Если какой-то рамки нет или она короче полоски, откалибруйте её вручную:
   **Ctrl+Alt+3**, чтобы выбрать полоску (выбранная рамка толще), затем курсор на левый край
   и **Ctrl+Alt+1**, курсор на правый край и **Ctrl+Alt+2**. Целиться лучше в верхнюю часть
   полоски, выше цифр.

Окно статуса можно перетаскивать мышью, позиция запомнится.

## Окно настроек

Открывается кнопкой **⚙ Настройки** в окне статуса или по **Ctrl+Alt+S**. Пока окно настроек
активно, утилита ничего не нажимает, потому что игра не в фокусе.

**Охота** — список сценариев. Чем выше сценарий в списке, тем он важнее (порядок меняется
кнопками ▲▼). Для каждого сценария задаётся:
- **Когда**: «После убийства цели», «Во время боя (цель жива)», «Нет цели N сек»,
  «По таймеру / по условию»;
- **Повторять не чаще, чем раз в N сек**: для скилла в бою это его интервал, для баффа,
  например, 1200 (20 минут);
- **Доп. условия**, например «Моё MP > 10» (не жать скилл без маны) или «Цели нет ≥ 1»
  (бафаться только вне боя);
- **Шаги**: клавиша и пауза после неё. Клавишу можно выбрать из списка, нажать кнопку ⌨
  и нажать нужную клавишу, или записать всю последовательность кнопкой «⏺ Записать с клавиатуры».

**▶ Проверить в игре** сохраняет настройки и выполняет сценарий, как только вы переключитесь
в игру (в течение 15 секунд).

Готовые сценарии: «После убийства моба» (включён), «Поиск цели», «Скилл в бою», «Бафф»,
«Банка HP/MP» (выключены, настройте клавиши и включите).

**Кнопки панели** — имена клавиш (`attack`, `next_target`, свои). **Полоски** — привязка окна,
автопоиск, допуск цвета и текущие значения. **Общие** — тестовый режим, интервалы, аварийная
пауза, скриншоты, горячие клавиши.

Править `config.json` вручную по-прежнему можно, но обычно не нужно.

## Как программа видит экран

10 раз в секунду под каждой полоской снимается полоса из 3 строк пикселей. По каждому столбцу
берётся медиана, поэтому цифры и рамка почти не мешают. Каждый столбец относится к одному из трёх
классов: **заливка**, **пусто** (цвет пустой части полоски, программа уточняет его сама во время
боя) или **чужое** (цифры, фон, перекрывшее окно). Процент — это граница, которая лучше всего
делит столбцы на «заливка слева, пусто справа».

У каждого чтения есть **самопроверка**:
- **достоверно** — картинка согласуется с моделью полоски, значение используется;
- **недостоверно** — картинка противоречивая (эффекты, перекрытие), значение **не используется**,
  программа ничего по нему не делает и ждёт ясной картинки. В окне статуса показывается «?»;
- **полоски нет** — окно цели закрыто. В окне статуса показывается «нет».

**Убил или потерял.** Если окно цели осталось на месте с HP 0, это убийство (труп в цели). Если окно
закрылось, когда HP было заметным (по умолчанию 15% и выше), это **потеря цели**: моба перехватили,
сняли цель Esc или он убежал. Потеря не считается убийством, для неё есть отдельный сценарий
**«После потери цели»** (следующая цель → атака, включён) и тип «Цель потеряна» в редакторе.
Статистика показывает потерянные цели отдельно.

**Сдвинутое окно цели.** Если окна цели нет на старом месте, программа раз в секунду ищет полоску
той же длины рядом (±160 px по горизонтали, ±100 px по вертикали). Найдя её дважды в одной точке,
переносит туда координаты. Перекалибровывать не нужно.

**Что видит программа** — блок на вкладке «Полоски»: увеличенная живая картинка каждой полоски и
под ней цветная строка, показывающая, как программа поняла каждый столбец (зелёный — заливка,
серый — пусто, оранжевый — чужое), с белой чертой на найденной границе. Если что-то читается
не так, здесь сразу видно почему. Там же блок **«Зрение»** с настройками.

## Кнопки панели скиллов: атака и следующая цель

В `config.json` есть блок с кнопками панели:

```json
"skill_keys": {
  "attack": "f1",
  "next_target": "f2"
}
```

Впишите сюда клавиши, на которых у вас на панели стоят **Атака** и **/nexttarget**
(значения по умолчанию — F1 и F2). В сценариях эти кнопки указываются по имени: `"@attack"`,
`"@next_target"`. Если перенесёте скилл на другую клавишу, достаточно поменять её здесь.
Можно добавлять свои имена: `"buff": "f5"`, `"heal": "alt+1"`.

Готовые сценарии:
- **После убийства моба** (включён): когда HP цели стало 0, жмёт «следующая цель»,
  ждёт 0,4 с и жмёт «атака».
- **Поиск цели** (выключен): если цели нет 4 секунды подряд (next target никого не нашёл,
  моба перехватили), снова жмёт «следующая цель» и «атака», не чаще раза в 3 с.
  Включите `"enabled": true`, чтобы цикл не останавливался.

**Ctrl+Alt+T** сразу выполняет «После убийства моба». Так удобно проверить, что нажатия доходят
до игры: стоя у мобов, нажмите сочетание и отпустите, персонаж должен взять цель и атаковать.

## Сценарии

Всё хранится в `config.json`. Изменения подхватываются на лету, перезапускать не нужно.

```json
{
  "name": "После убийства моба",
  "enabled": true,
  "priority": 10,
  "cooldown": 0,
  "conditions": [{"event": "target_died"}],
  "actions": [["f2", 0.4], ["f3", 1.2], ["wait", 0.5], ["esc", 0.3]]
}
```

- **conditions** — должны выполниться все:
  - `{"event": "target_died"}` — HP цели упало до 0;
  - `{"value": "my_hp", "op": "<", "than": 40}` — значения `target_hp`, `my_hp`, `my_mp` в процентах,
    операции `<  <=  >  >=  ==  !=`;
  - `{"value": "no_target_sec", "op": ">=", "than": 4}` — сколько секунд нет цели.
- **actions** — `[клавиша, пауза после нажатия в секундах]`. Кнопки из `skill_keys` — через `@`: `["@attack", 0.3]`. Клавиши: `f1`…`f12`, `0`…`9`, `a`…`z`,
  `esc`, `enter`, `space`, `tab`, стрелки `up/down/left/right`. Сочетания через `+`: `"ctrl+1"`.
  `["wait", 1.5]` — просто пауза.
- **priority** — чем меньше число, тем раньше проверяется сценарий. Одновременно выполняется один.
- **cooldown** — сколько секунд сценарий не повторяется после запуска.

Последовательность не обязательно писать руками. Нажмите **Ctrl+Alt+6**, нажмите кнопки в нужном темпе
и снова **Ctrl+Alt+6**. Нажатия вместе с реальными паузами запишутся в сценарий, указанный в
`record_into`.

Сценарий прерывается, если поставить паузу, выйти или переключиться из игры в другое окно.

## Тестовый режим

**Ctrl+Alt+7**: всё распознаётся, сценарии запускаются, паузы соблюдаются, но вместо нажатий
в лог пишется «[тест] нажал бы f2». Окно статуса становится жёлтым. Удобно настраивать
сценарии без риска.

## Аварийная пауза

Скрипт сам встаёт на паузу, пищит и делает скриншот, если:
- ваше HP стало 0 (смерть);
- HP упало на `hp_drop_percent` % за `hp_drop_seconds` секунд (по умолчанию 40% за 3 с).

Окно статуса становится красным и показывает причину. Текущий сценарий прерывается, даже если
он был в середине последовательности. Убийства во время паузы считаются в статистику, но
сценарий «после убийства» по ним не запускается. Продолжить можно через **Ctrl+Alt+0**.

Работает только если откалибровано «моё HP». Настройки в блоке `emergency`;
`hp_drop_percent: 0` выключает проверку падения.

## Скриншоты

При каждом запуске сценария и при аварии сохраняется снимок окна игры в папку `screenshots`
с цветными рамками вокруг считываемых полосок, как на оверлее. Если что-то сработало
не так, там видно, что скрипт видел. Хранятся последние 200 (`keep`). Снимки на каждое
убийство включаются через `on_kill`.

## Статистика

В окне статуса: убийства, убийства в час и активное время (без пауз и без времени, когда
игра свёрнута или неактивна). По **Ctrl+Alt+8** и при выходе в лог пишутся итоги: сколько раз
сработал каждый сценарий, среднее время на моба, число аварий.

## Прочие настройки

| Ключ | Что значит |
|---|---|
| `only_when_window_active` | нажимать клавиши, только когда окно игры активно |
| `check_interval` | как часто проверять экран, сек |
| `dead_confirm` | сколько проверок подряд HP цели должно быть 0 |
| `key_hold` | сколько держать клавишу нажатой, сек |
| `sound` | звуковые сигналы |
| `overlay`, `overlay_frames` | окно статуса и рамки на экране |
| `require_admin` | перезапускаться с правами администратора |
| `bars.*.tolerance` | допустимое отличие цвета пикселя от цвета полоски |

Журнал работы пишется в `hp_watcher.log`.

## Если что-то не так

- **Нажатия не доходят до игры.** Проверьте, что утилита запущена от администратора. Некоторые
  серверные защиты блокируют программные нажатия полностью, и тут уже ничего не сделать.
- **HP цели скачет или показывает 0 у живого моба.** Перекалибруйте полоску или увеличьте `tolerance`.
- **«Окно игры не найдено».** Снова нажмите Ctrl+Alt+5 в игре. Если в заголовке окна есть ник,
  оставьте в `window_title` только постоянную часть.
- Автоматизация может нарушать правила сервера, за это бывает бан.
